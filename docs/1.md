## Domain Search & Node Labeling (FG / FGRegex / FGPerm / ElementSymbol)

To support profiling of biosynthetic gene clusters (BGCs), mobile genetic elements, and order-flexible protein architectures, the node-labeling workflow has been extended beyond exact functional-group matching.  
The pipeline now supports **four domain search strategies**, which are auto-detected from the header of `functional_groups.txt` and used to assign `node.matching_protein_id` for downstream visualization, filtering, and analysis.

This document describes **only the functional behavior and responsibilities of the newly introduced or extended mechanisms**, with a focus on **regex-based** and **permutation-based** domain search.

---

## Overview of the Node Labeling Workflow

1. Read `functional_groups.txt` and detect the search type from the header (second column).
2. Parse query definitions into an internal query map.
3. Preprocess queries depending on search type:
   - compile regex patterns (FGRegex),
   - convert domain lists into sets (FGPerm).
4. Iterate over all nodes and assign `node.matching_protein_id` using the strategy-specific matching logic.
5. Resolve conflicts deterministically when multiple queries match the same node.

The detected search type is stored globally to ensure consistent labeling across all subgraphs.

---

## Supported Search Types

### FG (Exact Functional Group Match)

Matches `node.domain_annotation["functional_group"]` exactly against query strings.  
This is the original behavior and assumes standardized annotations.

---

### FGRegex (Order-Sensitive Regex-Based Search)

FGRegex enables **advanced, order-aware domain matching** using regular expressions applied to the node’s functional-group annotation string.

This mode is designed for:
- operon-like or BGC-like domain patterns,
- optional and repeated domains,
- overlapping functional definitions.

When multiple regex patterns match a node, conflicts are resolved using **mandatory-domain specificity scoring**.

---

### FGPerm (Order-Independent Permutation Search)

FGPerm enables **order-independent matching** based on the presence of a set of mandatory Pfam domains.  
Domain order, spacing, and repetition are ignored.

This mode is intended for:
- modular enzymes,
- shuffled domain architectures,
- cases where biological function depends only on domain presence.

Matching is based on **set inclusion**:

`mandatory_domains ⊆ node_domains`


---

### ElementSymbol (AMR Mapping Mode)

ElementSymbol is used for AMR-related workflows where labeling is based on `node.gc_id` rather than domain annotations.

In this mode, the query key and label columns are interpreted in reversed order.

---

## functional_groups.txt Header Semantics

The **second column of the header line** defines the search strategy:

- `protein_id	FG`
- `protein_id	FGRegex`
- `protein_id	FGPerm`
- `protein_id	ElementSymbol`

If the detected value is not one of the supported types, loading fails with a runtime error listing all valid formats.

---

## FGRegex: Mandatory-Domain–Based Conflict Resolution

Regex queries may overlap. To avoid ambiguous labeling, each FGRegex query is assigned a **specificity score** equal to the number of *mandatory Pfam domains* it contains.

### Mandatory Domain Rules

A Pfam domain is considered **mandatory** if:
- it matches `PF\\d{4,6}`,
- it is not part of a wildcard-only fragment (`.`, `.*`, `*`),
- it is not in an OR-expression (`|`),
- it is not optional (`?`, `*`, `{0,...}`).

When multiple regex patterns match:
- only patterns with the **maximum mandatory-domain count** are retained,
- remaining ties are merged into a compact label representation.

---

## FGPerm: Mandatory-Domain–Based Permutation Logic

FGPerm uses a similar specificity principle but operates on **domain sets instead of regexes**.

Each query defines a set of mandatory Pfam domains.  
A node matches if **all mandatory domains are present**, regardless of order.

If multiple FGPerm queries match:
- the query with the **largest mandatory-domain set** is selected,
- ties are resolved deterministically by retaining all maximal matches.

## Newly Added / Updated Functions (Functional Roles)

### `load_domain_search_result_and_search_type(domain_search_result_fp)`

- Parses `functional_groups.txt`
- Detects search type from the header
- Validates against supported search types (`FG`, `FGRegex`, `FGPerm`, `ElementSymbol`)
- Returns `(query_map, search_type)`

---

### `add_protein_ids(protein_to_fg_file_path)`

Main dispatcher for node labeling.

Responsibilities:
- routes labeling logic based on `self.search_type`
- assigns `node.matching_protein_id`
- guarantees exactly one deterministic labeling outcome per node

---

### FGRegex-Specific Functions

#### `count_mandatory_domains(FG_query: str) -> int`

- Computes the number of strictly mandatory Pfam domains in a regex query
- Used as a specificity score for overlap resolution

---

#### `convert_regex_fg_to_pattern(fg_to_protein_id)`

- Compiles FGRegex strings into `re.Pattern` objects
- Normalizes formatting and wildcard behavior
- Attaches metadata `(protein_id, mandatory_domain_count)` to each pattern

---

#### `get_matching_advanced_regex_queries(fg_annotation, pattern_to_query_name)`

- Matches a node annotation against all compiled patterns
- Returns protein IDs with the highest mandatory-domain score
- Returns `[None]` if no pattern matches

---

### FGPerm-Specific Functions

#### `convert_perm_fg_to_sets(fg_to_protein_id)`

- Converts comma-separated Pfam domain strings into sets
- Produces a mapping: `pattern_string → (protein_id, mandatory_domain_set)`

---

#### `has_all_mandatory_domains(fg_string, mandatory_domains) -> bool`

- Checks whether all mandatory domains are present in a node’s FG annotation
- Ignores order and repetition

---

#### `get_matching_permutation_queries(fg_annotation, pattern_to_query_name)`

- Evaluates all permutation queries against a node
- Retains matches with the largest mandatory-domain set
- Returns `[None]` if no query matches

---

### Database-Assisted Permutation Search

#### `search_proteins_by_mandatory_domains(mandatory_domains, DB_name, client, ...)`

- Performs order-independent protein search directly at the database level
- Optimized by starting from the least frequent mandatory Pfam domain
- Filters candidate proteins to retain only those containing all mandatory domains

---

## Notes on Integration

- Domain annotations must be loaded before node labeling
- `self.search_type` is fixed per run and applied consistently
- FGRegex and FGPerm share a **specificity-first** resolution philosophy
- FGPerm prioritizes biological presence over syntactic structure
