## MAGraph construction, profiling, and Pfam-constrained subgraph selection

This module implements the **graph-level core of MAGraph**, covering (i) neighborhood graph construction from genomic contexts, (ii) edge/node annotation and visualization, (iii) cohort-level subgraph profiling, and (iv) a newly added **Pfam-constrained subgraph filtering mechanism** that integrates directly with FGRegex logic.

---

## 1. MAGraph core data structures

### `MAGraphNode`

Represents a **gene family / gene cluster node** in the MAGraph.

Key attributes:
- `gene_name`: cluster representative ID (gc_id)
- `connection`: `{MAGraph_Edge → count}` (edge multiplicity)
- `depth`: node degree proxy (used as prevalence-like measure)
- `stringID`: STRING protein IDs mapped to this node
- `disease_group`: disease-group contribution bookkeeping

Nodes accumulate connections via `add_connection`, incrementing both edge count and node depth.

---

### `MAGraph_Edge`

Represents adjacency between two gene clusters on contigs.

Stored information:
- `edge_connection`: `frozenset({gc_id1, gc_id2})`
- `intergene_regions`: distances between adjacent genes
- `intergene_regions_samestrand`: distances when on same strand
- `intergene_regions_contigs`: contig IDs supporting the edge
- `best_stringscore`: maximum STRING interaction score

Edge scoring modes (`get_edge_score`):
- `mean`: mean intergenic distance
- `expression`: support count
- `vector` (used in igraph):  
  `(mean_distance, N_support, same_strand_rate, contig_list, string_score)`

---

## 2. MAGraph construction from gc neighborhoods

### `MAGraph_gc_neighbourhood`

Builds a **gene-neighborhood graph** from a list of `gc_id`.

Workflow:
1. Query neighborhood genes using  
   `get_gc_neighbourhood_directly_connected(...)`
2. Parse and order genes per contig (`_parse_gc_neighbourhood`)
3. Map `gene_id → gc_id`
4. Build:
   - nodes: unique gc_id
   - edges: adjacency of neighboring genes on contigs
5. Convert to `igraph.Graph` with rich edge attributes

This graph encodes **synteny-like relationships** across cohorts.

## 3. Graph extraction, trimming, and visualization

### Subgraph extraction
- Induced subgraphs based on gc_id lists
- N-hop neighborhood expansion
- Filtering by node prevalence (`depth`)

### Edge trimming
- `trim_graph_by_edge_weight(min_edge_N)`
- `remove_low_prev_edges(min_edge_N)`

### Visualization
- `annotate_subgraph(...)`
- `visualize_subgraph_igraph(...)`

Edge styling reflects:
- support (`N`)
- strand consistency
- intergenic distance

## 4. Graph-level abundance and prevalence estimation

### Abundance: `get_graph_abd_core(...)`

Pipeline:
1. Aggregate RPKM per gc_id
2. Sum gc_id abundances per query
3. Estimate graph abundance per sample as **median across queries**

Output:
- `{sample_id → RPKM}`

---

### Prevalence: `get_graph_prev_core(...)` (work-in-progress)

Intended logic:
- Presence/absence per gc_id per sample
- Query presence = OR across gc_ids
- Graph prevalence = aggregation across queries

(Current implementation contains TODOs and placeholders.)

## 5. Subgraph profiling across cohorts

### `profile_sub_graphs`

Profiles a list of MAGraph subgraphs with respect to cohort queries.

Filtering criteria:
- Each subgraph must match ≥ `min_matched_query` distinct queries

Annotations:
- Abundance / prevalence
- MSP taxonomy (`_gc_id2msp_id`, `_msp_id2taxaAnn`)
- Functional groups (`_gc_id2FG`)

Outputs:
- Sorted subgraphs
- Summary table:
  - number of samples
  - MSP annotation
  - number of gc_id
  - GTDB-Tk annotation
  - MetaPhlAn annotation

## 6. **New: Pfam-constrained subgraph profiling**

### `PFAMConstrainedProfileSubGraphs`

This class extends `profile_sub_graphs` by introducing **mandatory FGRegex constraints** at the **subgraph level**.

#### Motivation
Even if a subgraph matches enough query gc_ids, it may not contain a **required functional architecture** (e.g. mobile element marker domains). This class enforces that constraint explicitly.

---

### Required Pfam logic

#### Inputs
- `required_pfam_queries: Set[str]`  
  FGRegex-style queries (same syntax as FGRegex domain search)

#### Compilation
- Queries are compiled once using `compile_fg_query_pattern(...)`
- Stored as `{raw_query → re.Pattern}`

---

### Subgraph filtering rule

For each candidate subgraph:
1. Extract `{gc_id → FG_string}` via `_gc_id2FG`
2. Normalize FG strings (`replace(":::", "")`)
3. Accept the subgraph **iff**:
   - at least one gc_id FG string matches **any** required regex pattern

If not:
- subgraph is discarded
- `skipped_due_pfam` counter incremented

This guarantees:
> Every retained subgraph contains at least one gene family whose Pfam architecture satisfies the required FGRegex constraints.

---

### Key methods

- `_compile_required_patterns(...)`  
  Compiles raw FGRegex strings into regex patterns.

- `_graph_contains_required_patterns(gc_id2FG_dic)`  
  Core decision function for subgraph acceptance.

- `_normalize_fg_string(...)`  
  Removes internal FG delimiters before regex matching.

---

## 7. Conceptual integration

This Pfam-constrained profiling layer completes the **end-to-end FGRegex pipeline**:

- FGRegex at **protein search level**
- FGRegex at **gc_id annotation level**
- FGRegex at **subgraph (operon / neighborhood) level**

As a result, MAGraph analysis can now express and enforce **biologically meaningful domain-architecture constraints** consistently across:
- proteins
- gene clusters
- genomic neighborhoods
- cohort-level graph patterns
